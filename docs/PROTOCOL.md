# Протокол игры по сети (сервер игроков ⇄ клиент)

Единственное место, где описаны сообщения. Код: `server/protocol.py` (граница сервера), `server/ws.py` (кадры), `server/rooms.py` (комнаты), `server/relay.py` (транспорт); клиент — `arcade/lib/net-client.js`, поза — `arcade/lib/pose.js`. Проверяется тестами `tests/server/*`, `tests/unit/{pose,netclient,net-e2e}.test.js`, `tools/net-browser.cjs`.

**Версии протокола пока нет** — он меняется вместе с игрой. Перед первым выпуском для друзей добавим поле версии в `create`/`join` (единица E1 в `ROADMAP`).

## Транспорт
WebSocket, адрес `ws://хост:порт/ws` (для сайта на HTTPS — `wss://`). Сообщения не дробятся; кадр ≤ 1024 байта.

## От игрока к серверу
Текст (JSON, ≤ 512 символов):
| Сообщение | Смысл |
|---|---|
| `{"op":"create","name":"Аня"}` | создать комнату; создатель — хозяин, место 0 |
| `{"op":"join","code":"ABCD","name":"Боря","token":"…"}` | войти по коду; `token` (22 символа) — вернуться на своё место после обрыва |
| `{"op":"leave"}` | выйти |
| `{"op":"ping","t":123.4}` | проверка связи; сервер вернёт `pong` с тем же `t` |

Имя: без управляющих символов, ≤ 16 символов, пустое → «Игрок». Код: 4 символа из `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (без похожих I, L, O, 0, 1), регистр не важен. Лишние поля отбрасываются.

Бинарный кадр — **поза**, ровно 24 байта (числа «старший байт первым»):
| Байты | Поле | Кодирование |
|---|---|---|
| 0 | тип | `1` |
| 1–2 | `seq` | счётчик по кругу 65536 |
| 3–4, 5–6, 7–8 | x, y, z | 16 бит в границах мира (`WORLD`); вне границ — прижимается к границе |
| 9–10, 11–12, 13–14 | курс, тангаж, крен | 16 бит на [−π, π); крен после бочек сворачивается |
| 15–16 | скорость | знаковое 16 бит, ±120 м/с |
| 17 | руль | знаковое 8 бит, ±1 |
| 18 | флаги | `AIR 1, BRAKE 2, SKID 4, WALL 8, TUBE 16, PRO 32` |
| 19–22 | время `t` | мс по часам отправителя, 32 бита |
| 23 | — | резерв, 0 |

## От сервера к игроку
Текст:
| Сообщение | Когда |
|---|---|
| `{"op":"room","code","you","host","players":[{"slot","name","online"}],"token"?}` | при любом изменении состава; `you` — свой номер места 0–6; `token` — только самому вошедшему (и при его повторном входе) |
| `{"op":"error","code":"no_room"\|"full"\|"already_in_room"\|"bad_msg"}` | комнаты нет / 7 игроков / уже в комнате / сообщение отклонено |
| `{"op":"pong","t","srv"}` | ответ на `ping`; `srv` — время сервера |

Бинарный кадр, 25 байт: **номер места отправителя (1 байт) + 24 байта позы без изменений**. Себе позу сервер не возвращает. Сервер позу не читает, только проверяет размер и тип.

## Правила и пределы
- Комната — до 7 игроков; место — наименьший свободный номер; создатель — хозяин; если хозяин уходит или пропадает, хозяином становится наименьшее место среди тех, кто в сети (вернувшийся хозяин роль не забирает).
- Оборвалась связь — игрок помечается «не в сети», место держится 30 с; вернуться можно с токеном; затем место освобождается; пустая комната удаляется.
- Повторный вход в ту же комнату и повторный выход безвредны; из комнаты нельзя создать или войти в другую (`already_in_room`).
- Защита: ≤ 200 соединений; рукопожатие ≤ 5 с и ≤ 4 КБ; простой ≤ 60 с — закрытие 1001; текст ≤ 5 в секунду (пачка 10), позы ≤ 60 в секунду (пачка 30) — лишнее отбрасывается; 5 плохих сообщений подряд — закрытие 1008; кадр больше 1 КБ, дробление, служебные биты, кадр клиента без маски — закрытие 1002/1003/1009; медленному получателю позы пропускаются; Origin — по списку, если он задан при запуске.
- Не-комнатные клиенты и позы не из комнаты игнорируются молча.
- Токены выдаются из криптостойкого источника (`random.SystemRandom`).
