## Как пользоваться
```bash
npm test                              # тесты чистой логики (секунды)
npm run coverage                      # + coverage/lcov.info
tools/quality/setup.sh                # один раз: инструменты в .tools/ (нужно разрешение)

tools/check.sh [full]                 # общая проверка игры (теперь включает npm test)
```

## Как работаем над кодом (кратко из навыка, применительно к нам)
1. **Тест вперёд.** Падающий тест — увидеть, что падает по ожидаемой причине — наименьшая правка. Пример: `tests/unit/pose.test.js` (сначала красный «нет модуля», потом код).
2. **Чистая логика отдельно от игры.** Новое «мышление» (поза для сети, паспорт машины, таймер круга, правила гонки, миграция сохранения) пишем в `arcade/lib/*.js` чистыми функциями (без `scene`, `car`, DOM); они работают и в игре (классический скрипт), и в Node (`module.exports`). Разбор внешних данных — один раз на входе, внутри им верим.
3. **Тесты проверяют поведение**, а не устройство: зовём так же, как вызовет сеть/игра, смотрим на результат. Тест, который проходит при пустых функциях, выбрасываем.
4. **Выжившие мутанты** — дыры в тестах: дописать тест, убить мутанта. Пример: ручная проверка `pose.js` нашла 3 из 13 (длина пакета, старшие флаги, полный руль) — дописаны тесты.
5. **Сначала убрать, потом добавить.** Перед новым — вычистить дублирование и мёртвое.
6. **Маленькие упорядоченные коммиты:** почему, что изменилось, чем доказано.

## «Храповик» для старого кода
Игра (`arcade/js/*.js`, 26 файлов, ~6,5 тыс. строк в общей области имён) писалась до этих правил: в ней много функций со сложностью далеко за порогом и нет модульных тестов. Переписывать всё сразу не нужно и вредно. Правило:
- **Новый код** — проходит ворота целиком.
- **Старый код, который правим** — функцию, которой касаемся, доводим до порога *или* выносим изменяемую часть в `arcade/lib` под тесты; общий счёт не должен вырасти.
- **Базовая линия** — после первого разрешённого запуска сохраняем число функций выше порога и худшие (`docs/quality-baseline.md`); следим, чтобы оно только падало.
- Исключение, которое навык разрешает: длинные `switch`/таблицы данных не дробим ради цифры.

## Что остаётся за пределами этих инструментов
Приятность езды, красота, звук, нагрузка на телефон — проверяются глазами и руками (кадры 400×820, телефон заказчика). Метрики кода этого не заменяют.
